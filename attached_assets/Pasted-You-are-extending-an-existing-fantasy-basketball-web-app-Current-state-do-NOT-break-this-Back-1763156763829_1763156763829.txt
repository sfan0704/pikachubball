You are extending an existing fantasy basketball web app.

Current state (do NOT break this):
- Backend: Node + Express + TypeScript
  - Session-based auth + Yahoo OAuth
  - PostgreSQL + Drizzle
  - Existing Yahoo Fantasy MCP server and MCP client
- Frontend: React (already has some pages like chat/rankings)

Goal:
Add new “visualization” features as standard REST APIs plus React pages. These visualizations should help users understand their performance in a fantasy basketball league (no predictions, no AI recommendations).

Core visualization features to implement (MVP):
1) League overview:
   - League-wide category heatmap (teams x categories) showing relative strength per category.
2) Weekly matchup view:
   - For a selected week and team, show per-category bars for “my team vs opponent” and margins.
3) Schedule / games remaining:
   - For the current fantasy week, show a per-day calendar of which players play and total “games remaining” for my team (and optionally opponent).

Architecture requirements:
- Keep implementation simple, but make it easy to swap data sources later and to reuse the logic from a future MCP-based chatbot.
- Use a layered design:
  1) HTTP controllers (Express routes) under a prefix like `/api/viz/...`
  2) Domain-level “viz” services that know about leagues, teams, matchups, trends, etc.
  3) Data-source abstraction that hides how we fetch data (MCP, HTTP, DB, etc.)

Important:
- Define a data-source interface (e.g., “FantasyDataSource”) that exposes methods such as:
  - get league metadata and categories
  - get season-to-date team stats per category
  - get weekly matchup stats
  - get rosters for a week (for schedule/games-remaining)
- Implement ONE concrete data source that uses the existing Yahoo MCP client to call the current MCP tools.
- Domain “viz” services must depend only on this interface, not directly on MCP or raw Yahoo responses.
- Controllers should call the domain services and return UI-ready JSON for the frontend. Do not push business logic into React components.

Frontend requirements:
- Add new React pages for:
  - League overview (heatmap)
  - Weekly matchup view
  - Schedule/games-remaining
- Each page should:
  - Call the corresponding `/api/viz/...` endpoint.
  - Render charts using a charting library with good built-in support (e.g., ECharts or Recharts). You can choose the library and structure yourself.
- Keep React components focused on rendering (transforming the API response into chart config), not computing ranks or stats.

Constraints:
- Do not modify existing auth, MCP server definitions, or any working chat/ranking endpoints.
- Prefer adding new modules/routes/components over refactoring existing ones.
- Use TypeScript types for the visualization API responses so the frontend and backend stay consistent.

Please:
1. Inspect the current project structure.
2. Propose a minimal set of new endpoints and response shapes for:
   - League overview
   - Weekly matchup
   - Schedule/games remaining
3. Implement the backend (controllers + domain services + MCP-backed data source) for those endpoints.
4. Implement the corresponding frontend pages and chart components to render these views.
5. Keep changes as small and incremental as possible, integrated into the existing app.
